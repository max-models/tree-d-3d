This page runs tree-d-3d in your browser: [Pyodide](https://pyodide.org) is Python compiled to
WebAssembly, so nothing is sent to a server. Change the particles, the leaf capacity or the
opening angle and the quadtree is built again, and the field at every particle is computed by
the Barnes-Hut tree walk and by the direct sum. Move the target (the star) to see which cells
its walk takes.

A cell is split into four while it holds more particles than the leaf capacity, so the tree is
deep where the particles crowd and shallow where they are sparse. A cell of width
2*h* at distance *D* from the target is taken as one multipole (its charge, dipole and
quadrupole) when 2*h* < θ*D*, and opened otherwise. θ = 0 opens every cell, the direct sum; a
larger θ takes fewer, larger cells, cheaper and less accurate. The field errors are each
particle's error against the direct sum, over the RMS field; hover a particle for its own.
The same calls in a script:

```python
import numpy as np

from tree_d_3d import FlatQuadtree, Quad, direct_field

rng = np.random.default_rng(1)
pos = rng.uniform(-0.95, 0.95, (2, 2000))  # pos[0] is x
charge = rng.choice([-1.0, 1.0], 2000)
others = np.arange(2000)  # exclude each particle's own charge

tree = FlatQuadtree(pos, charge, Quad(0.0, 0.0, 1.0), leaf_capacity=8)
phi, field = tree.evaluate(pos, exclude=others, theta=0.5, softening=1e-3)
phi_ref, field_ref = direct_field(pos, pos, charge, softening=1e-3, exclude=others)
tree.node_center, tree.node_half, tree.node_depth  # the cells
```

In the browser the kernels run as vectorized NumPy instead of the compiled Pyccel loops, so the
timings are slower than on your machine. The page installs the tree-d-3d wheel built with the
site, and its dependencies, the first time it is opened; the browser keeps them afterwards.
